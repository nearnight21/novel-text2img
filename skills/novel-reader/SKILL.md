# 小说角色阅读材料

读取小说和角色事实，为视觉 Agent 生成简洁、可追溯的角色材料包，或回答其定向原文问题。

开始任务前读取 [文件协作协议](${HERMES_SKILL_DIR}/references/collaboration-protocol.md)。生成或更新角色材料包时，再读取 [材料包规范](${HERMES_SKILL_DIR}/references/source-brief-spec.md)。

## 快速判断

| 当前信号 | 执行动作 |
| --- | --- |
| 用户要求初始化当前项目 | 从模板创建 `novel-reader.project.yaml`，随后停止 |
| 当前角色存在 `pending` 原文问题 | 回原文检索并回答同一问题文件 |
| 当前角色缺少材料包，或用户明确要求重做 | 生成或更新 `source-brief.md` |
| 材料包存在且没有待读问题 | 简短说明没有阅读待办，然后停止 |

## 执行流程

1. 确定项目根目录。
   - 优先使用用户明确给出的路径。
   - 否则使用启动 Hermes 时的当前工作目录。
   - 只在该目录查找 `novel-reader.project.yaml`，不要向父目录或其他磁盘扩散扫描。

2. 初始化仅在用户明确要求时进行。
   - 读取 `${HERMES_SKILL_DIR}/templates/novel-reader.project.yaml`。
   - 在项目根目录创建同名配置文件。
   - 不猜当前角色，不创建角色档案，不读取整本小说；提示用户填写配置后停止。

3. 确定当前角色和时期。
   - 优先采用用户本轮明确指定的角色和时期。
   - 否则采用项目配置中的 `current_target`。
   - 若配置未指定，但当前交接目录中恰好只有一个 `pending` 问题，可使用该问题的角色。
   - 仍有多个可能目标时询问用户，不得静默选择。

4. 只选择一项下一步。
   - 用户本轮明确任务优先。
   - 其次处理当前角色的 `pending` 问题。
   - 再其次生成缺失的材料包。
   - 不在同一次唤醒中顺便处理其他角色。

5. 阅读原文。
   - 先读取当前角色事实档案，再在配置声明的正文范围内检索角色名、别名和相关场景。
   - 初次生成材料包时，应覆盖当前时期在全书中的相关出场，不可只取第一次外貌描写。
   - 阅读命中位置的上下文，区分叙述事实、人物评价、比喻、传闻和视觉 Agent 的旧推断。
   - 若同一特征随时间变化，按时期拆开，不得拼成一个不存在的综合形象。

6. 写入交接文件。
   - 材料包写入配置约定的 `<handoff_root>/<character_id>/source-brief.md`。
   - 定向问题在原文件中将 `status: pending` 改为 `status: answered`，并补入结论、原文、位置和不确定性。
   - 保留已有用户内容；只改当前任务涉及的文件。

7. 交付后停止。
   - 只报告写了哪个文件、核心结论和仍存在的真正不确定项。
   - 不开始视觉设计，不生成提示词，不制造新的审批或后续任务。

## 容易犯的错误

- 把剧情重要但无法画出来的信息塞进材料包。
- 用概括替代所有原文，使视觉 Agent 无法核对语义。
- 因为原文没写脸型或配色就阻塞交付。
- 把不同阶段的身材、伤势、衣着或形态混在一起。
- 为了“完整”扫描无关目录、整理全项目或创建证据系统。
- 把阅读 Agent 变成视觉设计师，擅自固定原文没有说明的外观。

## 完成前的唯一核对

只确认以下四项：

1. 当前角色和时期明确。
2. 所有硬特征都有原文依据或明确标注为推断。
3. 关键摘录带有可回看的章节或文件位置。
4. 没有修改约定范围外的文件。

不要运行项目测试、全量审计、状态检查或目录规范检查。
